CLAUDE CODE · DOCKER

Run Claude Code.
Expose less of your machine.

Run Claude Code in Docker through a separate remote node. The goal is to reduce what the tool can access or expose about your real public IP, host system and personal configuration, and reduce related account risk. Codex and other terminal tools can use it too.

WHY AIBOX

Your real IP, system and files.
A boundary for each.

aibox aims to limit Claude Code's direct access to your real machine environment. A remote exit and Linux container reduce exposure; here is what each boundary covers.

01 / FILES

It only sees the folders you pick

Only authorized project folders are mounted. Your personal home and ungranted configuration folders are not mounted. Reference folders can be read-only; project contents remain accessible to the tool.

02 / NETWORK

AI requests use the node's exit IP

Runtime traffic from the workspace goes through your remote proxy or VPN, exposing the node's exit IP to the destination. If it drops, the container goes offline to prevent fallback to your real public IP.

03 / ENVIRONMENT

A separate Linux environment

A container filesystem and separate home volume limit direct access to your host system and personal settings. The kernel, CPU architecture and some resource information remain visible.

HOW IT WORKS

Its own proxy,
separate from your host.

Claude Code runs in the workspace container, with networking handled by a separate gateway container (mihomo or a VPN). AI requests inside the container exit through a remote node to reduce exposure of your real public IP. Your host's Clash, VPN and system proxy keep working as usual.

  • Host untouched: the proxy and firewall rules live in the gateway container; none of your host's network settings change, and there's nothing to restore when aibox stops.
  • Container goes only through the node: the AI's container has no network interface of its own; traffic and DNS go through the gateway, IPv6 is off, and bypassing the tunnel is refused by the firewall.
  • No borrowing your local proxy: Clash on your machine has routing rules that may send traffic direct, so it can't be the upstream. Give aibox the subscription URL it uses instead.
  • Boundary: building the images downloads base images and packages over the host network.

GET STARTED

Three steps,
the wizard does the rest.

You need Docker and a proxy subscription, node links or a WireGuard config.

  1. [1]

    Install Docker

    On macOS use OrbStack or Docker Desktop and start it. On Linux use Docker Engine, then log out and back in once.

    macOS 
    brew install orbstack
    Linux 
    curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER

    Windows: install Docker Desktop with WSL2 integration enabled, then do everything below inside a WSL terminal.

  2. [2]

    Run the setup wizard

    It asks two things: egress (paste a subscription or node links, tested on the spot) and the project folders the AI may use. The first image build takes about 3–5 minutes.

    bash
    git clone https://github.com/seqi781/aibox ~/aibox
cd ~/aibox
./aibox init
    [>]Watch a real recording of ./aibox init (CLI output in Chinese)
  3. [3]

    Start in your project

    Run it inside a project folder. Log in once the first time; after that you stay logged in.

    bash
    cd ~/code/myapp
aibox claude

DOCTOR

Check the exit and leaks.
Inspect the isolation.

aibox doctor tests the exit IP, DNS and tunnel bypass paths, then reports the exit IP's type and risk. Passing covers only the checks performed; it does not establish that Claude Code cannot identify a device or that an account will avoid restrictions.

  • Tested, not just read: every check sends a real request from the container; any failure means a non-zero exit.
  • Disconnect test: with --full it simulates a tunnel drop, confirms traffic is blocked, then confirms recovery.
  • Environment report: checks exit IP type, risk records, time zone and language. Exit lookups use the proxy; host comparison lookups connect directly, exposing the host IP to those checking services. Redact reports before sharing.

FAQ

Before you start,
you might ask.

Is the goal to prevent bans? Can it fully hide my machine?

The goal is to reduce Claude Code's access to or exposure of your real public IP, host system and personal environment, and reduce related account risk. aibox provides a separate exit and container isolation, with no guarantee against bans or complete machine fingerprint masking.

Account identity, usage behavior, exit IP reputation and service rules still affect account status. Tool telemetry, account identifiers and container-visible kernel and hardware information remain.

Does the browser login also go through aibox?

Your host browser uses its own network settings; it does not automatically use the container's node. aibox constrains AI requests inside the workspace. Host browsers and other programs need separate network management.

How does it relate to Clash? Can I just use it?

They do different jobs: Clash handles your whole machine's browsing, aibox only the AI's egress — you can use both. aibox can't use your local Clash as its upstream; run aibox config and paste the subscription URL Clash uses.

Which systems are supported?

macOS (OrbStack recommended; Docker Desktop and Colima also work) and Linux (Docker 25+, Compose 2.24+). Tested on Ubuntu 24.04 arm64 with Docker 29; a physical Mac, SELinux and rootless Docker haven't been tested yet — reports welcome.

What about Windows?

Use it inside WSL2: install Docker Desktop with WSL2 integration and work in a WSL terminal, same as Linux.

What happens if the node goes down?

The container goes offline; it never falls back to your local network. It reconnects automatically when the node is back.

Is aibox affiliated with Anthropic or OpenAI?

No. aibox is an independent open-source project that runs these tools in a container; using them is subject to their own terms.

WHY AIBOX

真实 IP、系统、文件，
分别设一道边界。

aibox 的目标是尽量避免 Claude Code 直接接触真实机器环境。它用远程出口和 Linux 容器减少暴露；具体能隔离什么，下面逐项说明。

01 / FILES

只看得到你选的文件夹

只挂载你授权的项目目录，个人 home 和未授权的配置目录不挂载。参考资料可以设为只读；项目内容仍会交给工具。

02 / NETWORK

AI 请求使用节点出口 IP

工作容器的运行时流量强制经过远程代理或 VPN，让目标服务看到节点出口。节点断了，容器断网，避免回落到真实公网 IP。

03 / ENVIRONMENT

工具运行在独立 Linux 环境

使用容器文件系统和独立 home 卷，减少对宿主机系统与个人配置的直接访问。容器仍可见内核、CPU 架构和部分资源信息。

保护范围与仍然可见的信息
关注点aibox 提供仍然存在的边界
真实公网 IP容器内 AI 请求经远程节点发出，配合 DNS 防护与断线阻断。宿主机浏览器登录使用自己的网络；代理或 VPN 服务商仍能看到连接来源。
系统与机器信息独立 Linux 用户空间、容器 home 和运行环境。不隐藏全部硬件特征；内核、CPU 架构、资源信息及对齐的 UID/GID 仍可能被识别。
文件与身份信息仅挂载授权目录，容器内使用 /workspace/项目名 路径。项目文件、Git 元数据和主动传入的环境变量，仍可能包含真实路径或身份信息。
账号风控与封号以降低环境暴露相关风险为目标，提供出口检查和隔离机制。不修改工具遥测或账号标识；不保证无法关联设备，也不保证账号不被限制。

初始化、镜像拉取与构建、订阅预检及首次下载、节点域名的引导解析，可能使用宿主机或网关的直连网络。环境检查还会从宿主机查询本机 IP / DNS；这些不属于容器内 AI 请求的代理链路。

HOW IT WORKS

代理独立于主机，
两边互不影响。

Claude Code 在 workspace 容器里运行，联网交给独立的 gateway 容器（mihomo 或 VPN）。容器内的 AI 请求从远程节点出网，减少真实公网 IP 暴露；你电脑上的 Clash、VPN 和系统代理照常使用。

  • 主机不受影响：代理和防火墙规则都在网关容器里，主机的网络设置一项不改；停掉 aibox，也没有什么要恢复。
  • 容器只能走节点：AI 所在的容器没有自己的网卡，流量和 DNS 都经网关；IPv6 禁用，绕过隧道直连会被防火墙拒绝。
  • 不借用本机代理：本机的 Clash 有分流规则，可能让流量直连，所以不能当上游。把它用的订阅链接填给 aibox 即可。
  • 边界：构建镜像时下载基础镜像和软件包，走的是主机网络。

GET STARTED

三步上手，
剩下的交给向导。

需要准备：Docker，以及一个代理订阅、节点链接或 WireGuard 配置。

  1. [1]

    安装 Docker

    macOS 用 OrbStack 或 Docker Desktop，装好后启动它；Linux 用 Docker Engine，装完重新登录一次。

    macOS 
    brew install orbstack
    Linux 
    curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER

    Windows：安装 Docker Desktop 并开启 WSL2 集成，之后的步骤都在 WSL 终端里进行。

  2. [2]

    运行配置向导

    向导只问两件事：网络出口（粘贴订阅或节点链接，当场测试）和交给 AI 的项目文件夹。首次构建镜像约 3～5 分钟。

    bash
    git clone https://github.com/seqi781/aibox ~/aibox
cd ~/aibox
./aibox init
    [>]看一段真实录制的 ./aibox init
  3. [3]

    在项目里启动

    在项目文件夹里运行。第一次按提示登录，之后不用再登。

    bash
    cd ~/code/myapp
aibox claude
  • aibox claude启动 Claude Code
  • aibox codex启动 Codex
  • aibox shell进入容器终端
  • aibox tmux关掉终端，任务继续跑；再次运行回到原处
  • aibox status运行状态和出口 IP
  • aibox stop停止（数据保留）
  • aibox restart重启（改完配置后用）
  • aibox config修改网络出口和项目文件夹
  • aibox doctor检查隔离是否生效

也可以让 AI 帮你配：在 aibox 目录里对 Claude Code 或 Codex 说「帮我把 aibox 配好」，它会按 AGENTS.md 里的步骤操作，订阅链接和文件夹会先问你。

DOCTOR

检查出口与泄漏，
让隔离有据可查。

aibox doctor 实测出口 IP、DNS 和隧道绕过路径，最后汇总出口 IP 的类型和风险。检查通过只代表已检查项通过，不代表 Claude Code 无法识别设备或账号不会被限制。

  • 实测，不是读配置：每一项都在容器里真的发请求验证，有失败项时返回非 0。
  • 断线测试：加 --full 会模拟一次隧道断开，确认流量被阻断，再确认自动恢复。
  • 环境检测报告：查询出口 IP 类型、风险记录、时区与语言。出口查询经代理访问第三方服务；本机对比查询从宿主机直连，检测服务会看到本机 IP，分享报告前请脱敏。

FAQ

动手之前，
你可能想问。

目标是防封号吗？能完全隐藏真实机器吗？

目标是减少 Claude Code 获取或暴露真实公网 IP、本机系统与个人环境信息，以降低相关账号风控与封号风险。aibox 提供独立出口和容器隔离，不提供完整机器指纹伪装，也不保证防封号。

账号身份、使用行为、出口 IP 信誉和服务规则仍会影响账号状态。工具自己的遥测、账号标识与容器可见的内核和硬件信息，不会因此被消除。

登录时打开的浏览器也走 aibox 吗？

宿主机浏览器使用它自己的网络设置，不会自动走容器的节点。aibox 约束的是工作容器内的 AI 请求；主机上的浏览器和其他程序需要单独管理。

和 Clash 有什么关系？能直接用它吗？

两者管的不是一件事：Clash 管整台电脑上网，aibox 只管 AI 的出口，可以同时用。aibox 不能把本机 Clash 当上游，运行 aibox config，把 Clash 用的订阅链接粘贴进去即可。

支持哪些系统？

macOS（推荐 OrbStack，Docker Desktop、Colima 也可以）和 Linux（Docker 25+、Compose 2.24+）。已在 Ubuntu 24.04 arm64、Docker 29 上实测通过；真实的 Mac、SELinux 和 rootless Docker 还没实测过，欢迎反馈。

Windows 怎么用？

在 WSL2 里使用：安装 Docker Desktop 并开启 WSL2 集成，之后在 WSL 终端里操作，和 Linux 一样。

节点断了会怎样？

容器直接断网，不会改走本机网络。节点恢复后自动重连，不用重启。

aibox 和 Anthropic、OpenAI 有关系吗？

没有。aibox 是独立的开源项目，只是在容器里运行这些工具，使用时需要遵守它们各自的服务条款。
